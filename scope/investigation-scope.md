# Digital Forensics & Incident Response Investigation Scope

## 1. Case Overview

**Case ID:** DFIR-2026-001  
**Organisation:** Northstar Finance Ltd. (fictional)  
**Investigation Type:** Suspected workstation compromise  
**Investigator:** Security Analyst  
**Status:** Planned  

## 2. Incident Summary

An employee has reported unusual behaviour on their workstation. The security team has authorised a simulated investigation to determine whether the available evidence indicates suspicious activity, reconstruct relevant events, and recommend appropriate response actions.

All evidence used in this portfolio project will be synthetic and created for educational purposes.

## 3. Investigation Objectives

- Document the available evidence and its source.
- Calculate SHA-256 hashes to support evidence integrity verification.
- Examine simulated authentication, system, and file activity.
- Reconstruct a chronological incident timeline.
- Identify suspicious indicators and distinguish observations from assumptions.
- Assess the likely incident impact based on the available evidence.
- Recommend containment, eradication, recovery, and follow-up actions.

## 4. Scope

The investigation will cover:

- A fictional employee workstation.
- Synthetic event records and file metadata.
- Simulated authentication activity.
- Simulated suspicious file and system activity.
- Evidence documentation, integrity checks, and timeline analysis.
- A final investigation report with prioritised recommendations.

## 5. Out of Scope

The investigation will not involve:

- Accessing real employee devices or personal information.
- Collecting data from real company systems.
- Executing malware or other suspicious files.
- Accessing third-party systems.
- Performing destructive actions or making changes to production systems.
- Claiming that simulated findings represent a real-world compromise.

## 6. Evidence Handling

Each evidence item will be assigned an identifier and documented in an evidence inventory.

Where appropriate, SHA-256 hashes will be calculated to help verify that evidence files have not changed during analysis. Hashes support integrity checks but do not, by themselves, establish the authenticity or original source of evidence.

Analysis will be performed on simulated evidence in a controlled local working directory.

## 7. Investigation Methodology

The investigation will follow these stages:

1. Establish the scope and document the case.
2. Identify and inventory the available evidence.
3. Calculate and record evidence hashes.
4. Analyse simulated artifacts and event records.
5. Reconstruct the timeline.
6. Evaluate findings and alternative explanations.
7. Document conclusions, limitations, and recommended actions.

## 8. Ethical Considerations

This is an authorised educational exercise using fictional scenarios and synthetic data. The project is intended to demonstrate defensive investigation skills while protecting privacy and avoiding harm.
